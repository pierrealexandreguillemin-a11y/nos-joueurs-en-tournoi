## 1. Security — ISO 25010 + OWASP Top 10

### CRITIQUE

**SEC-1 — SSRF : pas de validation du protocole dans `/api/scrape`** (Confiance 92)

`app/api/scrape/route.ts:32-41` — Le hostname est valide (whitelist `echecs.asso.fr`), mais `parsedUrl.protocol` n'est jamais verifie. Un attaquant peut soumettre `file://echecs.asso.fr/etc/passwd` qui passe le check hostname.

Fix : `if (parsedUrl.protocol !== 'https:') return NextResponse.json({ error: 'Only HTTPS' }, { status: 400 });`

**SEC-2 — CSP affaiblie par `unsafe-inline` et `unsafe-eval`** (Confiance 100)

`vercel.json:29` — `script-src 'self' 'unsafe-inline' 'unsafe-eval'` neutralise toute protection XSS du CSP. CLAUDE.md documente "CSP: `default-src 'self'`" mais la realite est plus faible.

Fix : Migrer vers un CSP nonce-based (Next.js middleware) ou au minimum retirer `unsafe-eval` en production.

### HAUT

**SEC-3 — `/api/scrape` sans validation Zod ni authentification HMAC** (Confiance 95)

`app/api/scrape/route.ts:11-18` — Contrairement aux deux autres routes (`/api/events/sync`, `/api/events/fetch`), la route scrape valide l'URL avec un simple `typeof`, sans schema Zod ni token HMAC. Inconsistant avec le claim CLAUDE.md "Zod schemas strictes sur toutes les routes API".

**SEC-4 — Schemas Zod sans bornes superieures** (Confiance 85)

`src/lib/schemas.ts:56-61` — `events: z.array(eventSchema)` sans `.max()`, strings sans `.max()`. Un payload valide de 1 MB peut contenir des structures profondement imbriquees. OWASP A03/A04.

**SEC-5 — Reponse HTML FFE sans validation taille/content-type** (Confiance 80)

`app/api/scrape/route.ts:54-58` — La reponse FFE est retournee sans verifier `content-type: text/html` ni limiter la taille du HTML.

### MOYEN

**SEC-6 — CORS : pas de handler OPTIONS sur les routes API** (Confiance 82)

`vercel.json:39-56` — Les headers CORS sont definis mais aucun `export async function OPTIONS()` n'existe dans les routes. Certains navigateurs rejetteront le preflight.

**SEC-7 — `NEXT_PUBLIC_SYNC_SECRET` = cle publique** (Confiance 80, documente)

`src/lib/hmac.ts:13` — La cle HMAC est dans le bundle client. Tout visiteur peut forger des tokens. Documente dans CLAUDE.md comme "defense-in-depth, pas auth forte". Pas un bug, mais le niveau reel de protection est faible.

## 2. Reliability — ISO 5055

### HAUT

**REL-1 — Silent catch dans `fetchPairingsForRound`** (Confiance 90)

`src/hooks/useTournamentSync.ts:27-29` — `catch { return []; }` avale toutes les erreurs sans logging. ISO 5055 §7.2 interdit de supprimer l'information d'erreur. Le `[]` retourne est indistinguable de "pas d'appariements".

**REL-2 — Import JSON sans validation Zod** (Confiance 85)

`src/lib/storage.ts:49`, `src/components/EventsManager.tsx:368` — `JSON.parse(...) as ExportedEvent` sans schema Zod. Un fichier importe corrompu peut ecrire des donnees invalides en localStorage. CLAUDE.md dit "Reutiliser les schemas Zod de `schemas.ts`".

**REL-3 — `window.location` sans guard SSR dans `storage-share.ts`** (Confiance 83)

`src/lib/storage-share.ts:101` — `window.location.origin` est appele sans verifier `typeof window !== 'undefined'`. Le fichier n'a pas de directive `'use client'`. Si appele cote serveur : `ReferenceError`.

### MOYEN

**REL-4 — Cast `as ValidationState` contourne la verification structurelle** (Confiance 82)

`app/api/events/sync/route.ts:44` — Apres validation Zod, le resultat est cast avec `as ValidationState` au lieu de laisser TypeScript verifier la compatibilite structurelle. Si le type evolue, le cast masquera le desaccord.

## 3. Accessibility — WCAG 2.1 AA

### CRITIQUE

**A11Y-1 — Bouton icone copie sans `aria-label`** (Confiance 95)

`src/components/ShareEventModal.tsx:80-92` — Le bouton copier/check a `title` mais pas `aria-label`. Les icones `Copy`/`Check` n'ont pas `aria-hidden="true"`. WCAG 4.1.2.

**A11Y-2 — Bouton icone partage (fallback) sans nom accessible** (Confiance 88)

`src/components/ShareEventModal.tsx:177-179` — Le trigger par defaut du ShareEventModal n'a ni `aria-label` ni `title`. L'icone `Share2` n'a pas `aria-hidden`. WCAG 4.1.2.

### HAUT

**A11Y-3 — `BackgroundPaths` ignore `prefers-reduced-motion`** (Confiance 92)

`src/components/BackgroundPaths.tsx:36-54` — Framer Motion ne respecte pas le CSS `animation-duration: 0.01ms`. Le hook `useReducedMotion()` de Framer n'est pas utilise. Les animations SVG continuent meme si l'OS demande reduced-motion. WCAG 2.3.3.

**A11Y-4 — Menu `ClubHeader` sans gestion du focus** (Confiance 85)

`src/components/ClubHeader.tsx:63-81` — Le dropdown custom `role="menu"` ne deplace pas le focus sur le premier item a l'ouverture. Tab quitte le menu au lieu de naviguer entre les items. Pas de `aria-activedescendant`. WCAG 2.1.1.

**A11Y-5 — Canvas `HalftoneWaves` non cache de l'arbre a11y** (Confiance 85)

`src/components/HalftoneWaves.tsx:281-287` — Le `<canvas>` decoratif n'a pas `aria-hidden="true"`. Un lecteur d'ecran peut tenter d'annoncer l'element. WCAG 1.1.1.

**A11Y-6 — `ClubSelector` : `aria-label` ecrase le label visible** (Confiance 80)

`src/components/ClubSelector.tsx:38` — Le `<select>` a a la fois `htmlFor` (label visible "Choisissez votre club") et `aria-label="Selectionner un club"`. L'algo de calcul du nom accessible donne priorite a `aria-label`, ignorant le label visible. WCAG 1.3.1.

### MOYEN

**A11Y-7 — `dialog-title-gradient` avec `-webkit-text-fill-color: transparent`** (Confiance 90)

`src/styles/globals.css:486-493` — Le texte rendu transparent par gradient-clip peut ne pas etre compute comme nom accessible sur iOS VoiceOver < 16. Fragile. WCAG 4.1.2.

**A11Y-8 — Debug panel trigger sans `aria-label`** (Confiance 95, dev-only)

`src/components/DebugPanel.tsx:107-115` — Bouton icone `Bug` sans `aria-label` ni `aria-hidden`. Dev-only mais viole WCAG 4.1.2.

## 4. Maintainability — ISO 5055

### HAUT

**MAINT-1 — `sonarjs/no-nested-functions` dans `parser.ts`** (Confiance 95)

`src/lib/parser.ts:188,228,241` — `parseResults` contient des callbacks `.each()` avec des callbacks imbriques (3 niveaux). La regle `sonarjs/no-nested-functions: error` est active. A verifier : le pre-push gate passe actuellement, ce qui suggere un override non detecte ou une tolerance de la regle pour les callbacks de methode.

**MAINT-2 — `sonarjs/no-duplicate-string` dans EventsManager** (Confiance 92)

`src/components/EventsManager.tsx:109,121,134` — La chaine `"text-primary hover:text-primary/80 hover:bg-primary/10"` apparait 3+ fois. A verifier contre la configuration sonarjs (le seuil par defaut est 3).

### MOYEN

**MAINT-3 — `EventsManager` a la limite de 80 lignes** (Confiance 85)

`src/components/EventsManager.tsx:427-510` — 79 lignes effectives (apres skip blanks+comments). Un seul ajout le fera depasser.

**MAINT-4 — `sonarjs/no-duplicate-string` dans TournamentTabs** (Confiance 80)

`src/components/TournamentTabs.tsx` — `"glass-card"` apparait 5 fois.
